# AI 周公解梦规格

## 产品目标

构建一个本地可运行的梦境解读工具。用户输入梦境后，系统检索本地周公语料，并通过 AI Hub 项目级代理调用当前选择的 GPT 型号，生成结构化报告、本机历史和分享图。

## 技术结构

- Frontend：React + Vite + TypeScript
- Backend：Express + Zod
- Model：AI Hub 项目级代理，仅允许 `openai` 路由和 `gpt-*` 型号
- Storage：`data/` 下的本地 JSON/JSONL 文件；共享运行时使用持久化 shim
- RAG：本地周公语料、规范化与检索器

## 统一模型约束

- 项目页面不显示、接收或保存 API Key。
- 页面顶部统一模型选择器是唯一型号入口。
- 项目内部不提供厂商按钮或模型下拉框。
- Hub 项目配置未就绪时禁止生成，不提供本地 AI 预览。
- 请求 schema 和 Hub 调用边界都拒绝非 `openai` 路由及非 `gpt-*` 型号。

## 安全边界

- 输出只用于娱乐和自我反思。
- 不做确定性命运、医疗或心理健康判断。
- RAG 引用必须来自服务端检索结果，模型不得发明原文。
- 日志不得记录密钥、管理员凭证或请求头中的项目令牌。

## 验收

- `POST /api/interpret` 只接受 Hub 当前 GPT 型号。
- 所有生成请求携带项目 ID、项目路径及可选项目令牌发送给 Hub。
- 历史与用量统计只记录真实 Hub 生成。
- 单元测试覆盖 schema、Hub 边界、JSON 解析、RAG 和分享功能。
