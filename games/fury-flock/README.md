# 怒羽突击 · Fury Flock

一款原创的 2D 物理弹射浏览器游戏。它保留“拉弓、预判抛物线、连锁摧毁”的玩法乐趣，但角色、场景、界面、关卡与音效均为原创实现。

## 运行

```powershell
npm install
npm run dev
```

浏览器打开 Vite 输出的本地地址即可。生产构建：

```powershell
npm run build
```

默认本地地址是 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。打开后先进入明亮的品牌首页；点击“选关编队”进入独立作战部署页，在 40 个关卡中选择目标并为每一发弹药安排小鸟。点击“开始第 N 关”会直接进入战斗，不再经过第二个整备界面。

游戏官网使用轻量 Hash 分页，不依赖后端路由：`#home` 为品牌首页，`#mission` 为选关编队，`#roster` 为完整战场图鉴，`#play` 表示正在游戏。战术手册页面与导航入口已经移除。游戏画面左下角的“主站”按钮可以安全结束当前任务并返回选关编队页。

独立作战部署页会随选中关卡切换真实关卡背景，并显示难度、目标数、弹药数和推荐小鸟。“逐发编队”中的每个槽位就是一发真实小鸟，战斗严格从左到右发射。手机端使用可横滑的关卡路线，并把弹药槽和四鸟选择压缩为触屏友好的紧凑网格。

游戏内整备与结算菜单采用“暮云悬崖作战台”视觉主题：Image2 生成的无文字远景底图提供堡垒、羊皮地图和暮色氛围，DOM/CSS 负责黄铜节点、暗木面板、鸟队卡片、暂停/结算层和全部交互状态。桌面端使用双栏战术台，移动端改为单列滚动并持续保留开始按钮；素材来源与处理契约见 `art-source/ui/README.md`。

真正的游戏外部官网使用独立的 Image2 Hero 场景，并把游戏中的四张正式鸟素材叠加到飞行通道上，避免角色形象漂移。官网采用明亮晴空主题：首页只承担品牌展示与分流；选关编队页承载关卡和逐发装填；战场图鉴用作战档案牌完整介绍四只怒羽与三种苔鼻猪的属性、特点和技能。内页作战桌背景补充弹弓、材质块、绳索、羽毛、飞鸟剪影和猪形投影。网站分页、响应式布局和素材契约见 `art-source/site/README.md`。

## 操作

- 官网“选关编队”页先点弹药槽、再点小鸟完成逐发编队；选择后自动前进到下一槽。
- 键盘用数字键 `1`–`5` 选择弹药槽，`↑` / `↓` 更换当前槽的小鸟，方向键左右切关，按 `Enter` 开始。
- 鼠标或触屏按住弹弓上的怒羽，向左拖拽并松开发射。
- 如果拖拽不方便，可点击右下角“发射”按钮，或按空格键使用默认弹道。
- 小鸟能力无需二次点击：红鸟中心线命中自动精准破点；蓝鸟进入战场或接近目标后在当前位置短暂停顿并同点三分裂，最迟 1 秒触发；黑鸟飞出弹弓安全区后，首次撞击自动爆炸；绿鸟自动无伤穿过第一个建筑障碍，该障碍不会受伤。
- `R` 重开本关，`Esc` 暂停/继续。
- 暂停和关卡结算界面均可返回独立的选关编队页重新部署。
- 拖拽离开游戏画布后松手仍会发射，适配鼠标与触屏边缘操作。
- 浏览器或系统取消触摸时会把小鸟放回弹弓，不再把 `touchcancel` 误判为松手发射。

## 出战小鸟

- **赤羽先锋（红鸟）**：均衡弹道；高速命中障碍中心线时触发“精准破点”，该目标本发首次精准命中造成 `1.32×` 伤害并奖励 `320` 分。
- **铁喙重炮（黑鸟）**：速度较慢但撞击力强；完整飞出弹弓右侧安全区前不会起爆，越过安全边界后的首次碰撞自动触发范围爆炸。
- **风翎游侠（蓝鸟）**：速度快、弹道高；离弦至少 `480ms` 后，进入战场中段或接近目标便自动三分裂；三个分身在飞鸟当前位置重合 `90ms`，再从同一点沿三条纵向轨迹释放，慢速飞行最迟 `1000ms` 兜底触发。
- **翠影穿梭（绿鸟）**：速度与弧线均衡；首次碰到建筑方块或平台时自动穿透且不伤害该障碍，鸟体完全越过障碍另一侧后才恢复正常碰撞。

四种小鸟具有不同轮廓、颜色、尾迹、质量、初速度、自动能力、撞击倍率和合成撞击音色，不是只替换外观。红鸟每个结构每发最多奖励一次精准命中；蓝鸟每发最多分裂一次、场上最多形成三只；黑鸟每发只在越过发射安全边界后的首次碰撞爆炸一次，起步触地与火铳命中都不会引爆；绿鸟每发只穿透第一个建筑障碍，敌人与地面不会消耗穿透次数。

同一关可自由混编，例如“赤羽 → 铁喙 → 风翎 → 赤羽”。HUD 会显示真实剩余队列，每一发都使用对应小鸟的物理、技能、尾迹和撞击音色。各关根据结构提供 4–5 个槽位；切换关卡时保持顺序，新增槽位用上一槽的小鸟补齐。

四只角色的正式形象由 GPT Image 2 生成并经过透明化、逐只裁切或独立归一化与 256×256 统一画布处理。整备界面、弹药 HUD 和战斗场景共用同一套正式素材；原有程序化小鸟纹理仅作为图片加载失败时的运行时兜底。素材来源与处理契约见 `art-source/birds/README.md`。

敌方目标也使用 GPT Image 2 生成的“苔鼻盗贼”系列正式形象：普通盗贼、铁盔守卫和火铳哨兵保留同一套立耳与折耳、宽鼻和头巾造型语言，整备堡垒预览与战斗场景共用 `public/assets/targets/` 下的正式素材。程序化目标纹理仍作为加载失败时的兜底，完整素材契约见 `art-source/targets/README.md`。

第 5–40 关各有一只“铁盔苔鼻”：它使用同一角色的防弹头盔变体素材，首次有效命中只会击碎头盔并切回普通苔鼻，不扣生命；破甲后有 260ms 反馈保护，避免同一次碰撞连锁立刻抹掉破甲状态，之后的伤害才正常结算。头盔不改变目标碰撞体、密度、分数或站位。

第 4、6、8、10、13、15、18、20、22、23、26、28、30、31、33、35、36、37、39、40 关配置“火铳哨兵”，其中第 26、31、36 与 40 关采用双火铳交叉锁定：每枚怒羽离弦并清出弹弓后，存活的哨兵会显示“火铳就绪”，随后依次用 320ms 瞄准线锁定并必定开火；玩家需要在发射前优先规划哨兵击杀路线，锁定期间若哨兵被连锁破坏也会中断拦截。所有怒羽被命中后偏转约 22.5° 并保留 92% 速度，火铳本身不会触发黑鸟爆炸；开火后显示“空膛”，下一枚怒羽出现时重新装填。火铳猪与铁盔猪不会叠加在同一目标上。

40 关使用 31 张 GPT Image 2 环境背景；前 23 关各有独立画板，第 27、28、31、32、37、38、39、40 关使用专属画板，其余后期关按战术主题复用最相符的环境。第 37–40 关分别使用霜镜折廊、长风三叠台、黑潮爆心库和万羽天门专属背景，堡垒结构、平台、目标、推荐鸟和预览仍由独立关卡配置驱动。原始 PNG 由 `art-source/backgrounds/process_background.py` 按需中心裁切为 16:9、缩放到 1200×675，并输出质量 86 的 WebP。素材映射和重建方式见 `art-source/backgrounds/README.md`。

## 结构

- `src/game/simulation`：与渲染器无关的计分和关卡状态。
- `src/game/content`：40 关结构数据与四种小鸟配置。
- `src/phaser/scenes`：Phaser/Matter 场景和交互适配。
- `src/phaser/view`：程序化纹理、碎屑、残影和镜头反馈。
- `src/ui`：DOM 品牌首页、独立选关编队、完整战场图鉴、测试兜底整备页、HUD、暂停和结算。
- `art-source/backgrounds`：31 张原创关卡环境画板的 Image2 提示词、原始输出、确定性处理脚本及运行时映射。
- `art-source/ui`：游戏内整备/结算菜单背景的 Image2 提示词、原始输出、确定性处理脚本与 QA 预览。
- `art-source/site`：外部游戏官网 Hero 的 Image2 提示词、原始输出、确定性处理脚本与 QA 预览。

更完整的玩法范围见 `GAME_DESIGN.md`，手感预算见 `FEEL_TUNING.md`。

## 验证

```powershell
npm test
npm run build
npm run test:e2e
```

开发模式下可通过 `window.__furyFlock.getState().birdTelemetry` 读取逐发报告：包含鸟种、初速度、伤害、撞击/摧毁/能力/通关得分、技能触发和每鸟聚合。报告会明确标记 `comparisonStatus: instrumented-not-run`；它是可复跑的真实物理逐发探针，不冒充尚未执行的单调策略/探索策略胜率比较。

端到端套件覆盖桌面 Chromium 与 Pixel 7 手机视口，包括官网首页选关编队并直达战斗、逐发混编、真实装填顺序、混合 HUD、40 关载入、拖拽/快捷发射、画布外松手、触摸取消保护、红鸟精准破点、蓝鸟机会式同点自动三分裂、黑鸟撞击爆炸、绿鸟首障无伤穿透、火铳哨兵自然进入瞄准、自动拦截、逐回合重装与黑鸟安全偏转、暂停/结算返回和关卡推进。自动化环境通过 `VITE_SITE_ENTRY=play` 保留旧整备页作为玩法测试兜底入口。
