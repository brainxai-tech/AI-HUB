# AI HUB 中转盈利闭环实施计划

## 目标

在现有“中转站目录 + 倍率比较”基础上，增加一个可安全演示、可逐步接入生产支付的自营中转网关 MVP：用户注册/登录、余额账本、平台 API Key、模型销售价配置、调用量记录和管理端测试充值。真实支付、第三方平台授权和多上游自动路由不在本阶段伪造。

## 克制的产品边界

- 主站继续只保留“模型图鉴 / AI 项目 / 模型中转商服务”三个板块，不增加新的一级菜单。
- 价格比较仍是中转商服务的首屏重点；账户、余额、Key 和账单只通过一个“API 控制台”入口进入独立页面。
- 中转服务采用“模型优先”流程：先选模型，再只展示支持该模型的代理商，最后进入代理商详情。
- 默认状态只显示必要的余额、Key 数量和最近消费，详细账单、价格来源和管理操作采用渐进展开。
- 不在主站放置假充值按钮、夸张的利润宣传或未核验的“最低价”标签。

## 架构决策

- 现有项目级 `x-hub-project-token` 继续只服务 AI HUB 内部项目，不与用户商业 API Key 混用。
- 新增独立的 relay commerce 存储文件，余额使用整数微元（1 元 = 1,000,000 微元），避免浮点误差。
- 密码只保存基于 Node `scrypt` 的 salted hash；会话只保存 hash，客户端使用 HttpOnly、SameSite Cookie。
- 用户 API Key 只在创建时返回一次，持久化只保存 hash 和掩码前缀。
- 未配置真实上游价格或 API Key 时，目录仍展示“待配置”，网关拒绝调用，不生成虚假账单。
- 充值接口先返回“支付未配置”；管理员测试额度接口只用于本地验收，不代表真实收款。

## 垂直切片

### Phase 1：账户与钱包基础

- [ ] 新增 `relay-commerce.mjs`：账户、会话、Key、余额和价格规范化、账本操作。
- [ ] 新增注册、登录、退出、当前账户、钱包和 Key API。
- [ ] 新增管理员测试入账 API，所有余额变更写入不可变账本。

验收：注册后能登录；刷新页面仍保持会话；创建/删除 Key；余额和账单只返回当前用户数据；未授权请求全部拒绝。

### Phase 2：销售价格与计费网关

- [ ] 新增管理员模型销售价 API，维护上游成本、销售价格、倍率、来源和核验日期。
- [ ] 新增统一 Relay Chat Completions 入口，使用平台 Key 调用已配置上游。
- [ ] 按上游返回的 input/output token 计算费用，余额不足时拒绝，失败请求不扣费。
- [ ] 增加幂等请求号、调用记录和基础限额。

验收：模型未配置时不可调用；成功调用生成一次 usage 账单；重复幂等请求不重复扣费；上游失败不产生 usage 扣费。

### Phase 3：用户体验与运营面板

- [ ] 在 Hub 中增加“API 控制台”入口和独立页面。
- [ ] 展示余额、已创建 Key、模型销售价、调用量和消费记录。
- [ ] 提供“充值通道尚未配置”的明确状态，不放置假支付按钮。
- [ ] 在中转站详情页区分“目录导流”和“自营中转”，引导用户使用统一 API。

验收：桌面和 390px 移动端可完成注册、登录、查看余额、创建 Key、查看价格和调用示例；无控制台错误。

### Checkpoint

- 每个 Phase 完成后运行 `npm run verify`、安全扫描和接口冒烟测试。
- 生产前必须补齐真实上游授权、支付服务、退款、税务/发票、风控和 SLA 监控。

## 风险与边界

| 风险 | 缓解 |
|---|---|
| 上游价格或授权变化 | 必须保存来源 URL、核验日期和人工启停开关 |
| 余额浮点误差 | 全部使用整数微元 |
| Key 泄露 | 只显示前缀，服务端只保存 hash，日志禁止记录原 Key |
| 重复扣费 | 要求并处理 `Idempotency-Key`，账本记录唯一请求号 |
| 滥用和高额账单 | 用户/Key/模型限额，余额不足硬拦截，记录审计事件 |
| 假充值 | 本阶段不开放公开充值，只允许管理员测试入账 |
